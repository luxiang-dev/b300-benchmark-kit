# 通用服务器验货与全流程可视化

本项目支持 Ubuntu 单节点 1–64 张 NVIDIA GPU，以及不依赖 GPU 的整机检查。内置 B300/B200/H100/H200/A100/A30/A40/A10/L40S/L40/L4/T4、RTX 3090/4090/5090 架构规则；其他 NVIDIA 型号可以采集身份、尝试兼容 CUDA 负载，但缺少内置型号规则时保持 REVIEW，需厂商确认。AMD/Intel GPU 负载不在本版本范围内。

**技术 PASS 只涵盖本次实际执行项目，不代表收货合格。** 必须取得采购 BOM、实物序列号/厂商保修核验和机型验收规范；未知配置不会由自动识别补成合格标准。CPU 测试、模拟 GPU 日志和浏览器预览均不代表实际 GPU 验证。

## 1. 选择准备方式

| 主机 / 目的 | 准备内容 | 是否需要 Docker / NVIDIA 驱动 |
|---|---|---|
| 无 GPU，或仅核验 CPU/RAM/存储/NIC/BMC | 项目源码、Python 3；按 OEM 运维规范准备 pciutils、dmidecode、smartmontools、ipmitool 等只读工具 | 不需要 |
| NVIDIA 身份信息采集 | 源码、Python 3、适配实际 GPU 的驱动 / nvidia-smi | CUDA 补充核验需要本地兼容镜像 |
| NVIDIA 显存 / 计算 / 多卡稳定性 | 硬件离线包、驱动、Docker、NVIDIA Container Toolkit | 需要 |
| 预置 Qwen/SDXL 模型 | 完整离线包；快速模式每卡至少 12 GiB，完整/长测至少 32 GiB；可确认的 Ampere 或更新架构 | 需要；容量门槛不保证所有负载都能装入 |
| Oracle NCCL / DeepSeek MLPerf 原有参考 | 专项固定资源及 **8×B300** 环境 | 条件不符时禁止套用 |

在联网、CPU 架构匹配的 Linux 准备机制作 GPU 包：

```bash
bash prepare_offline.sh --hardware-only
python3 bundle.py verify --hardware-only
```

要预置模型时去掉 `--hardware-only`。准备过程下载镜像/权重；目标机器测试阶段离线。默认 NVIDIA PyTorch 25.10 镜像使用 CUDA 13：它不是适合全部历史 GPU 的通用运行时。老卡应先按 NVIDIA 支持矩阵选择兼容 PyTorch/CUDA 镜像，在准备机设置 `BASE_IMAGE` 后重新构建/封装；不要仅升级驱动后声称支持。不同运行时的原始版本、架构和镜像 ID 会保留。NCCL 测试二进制改为编译该工具链支持的 GPU 架构，不再只编译 Blackwell。

准备脚本接受 `BASE_IMAGE` 和 `TARGET_ARCH`；更换 GPU 镜像仍须含匹配的 CUDA 编译器、PyTorch、NCCL 库及头文件。实际 CUDA 探针必须成功，不能以型号文字替代运行时兼容性验证。为兼容旧准备包，镜像标签/归档仍叫 `b300-test:1.0` / `images/b300-test.tar`，不表示仅支持 B300。

源码更新后必须重建/重新封装；旧哈希封装不能验证新代码。严禁从卖方日志反推采购承诺，或清除 ECC/SEL 等错误历史后测试。

## 2. 启动界面（一次主机启动）

把整个项目/准备包复制到 Ubuntu 本地 SSD，使用有结果目录写权限的运维账号：

```bash
python3 dashboard.py --port 8765 --results /data/server-acceptance/results
```

本地浏览器打开 `http://127.0.0.1:8765`。Windows PowerShell 另开终端，保持 SSH 隧道运行：

```powershell
ssh -N -L 8765:127.0.0.1:8765 用户名@Ubuntu服务器IP
```

然后 Windows 浏览器打开同一地址。服务默认监听所有 IPv4 网卡，支持直接局域网访问及你配置的公网映射；无需 SSH 时直接访问外部 URL。仅本机使用加 `--host 127.0.0.1`。网络、代理和可选认证见 [公网映射说明](公网映射访问.md)。Windows `python dashboard.py --preview` 是只读界面，不启动测试、不生成假 GPU/性能。

## 3. 后续全部通过可视化界面操作

1. **准备与清单**：查看真实型号、数量、显存、MIG/ECC 和镜像状态。GPU 项目点击“导入离线镜像”，后台先核验封装再导入；纯 CPU 项目跳过此步骤。
2. **验货目标**：选择合同指定 GPU 型号、填写采购卡数。型号未知选“自动识别”；数量未知填 0，表示按实测卡数运行，**无法检查是否少配**。选择显存覆盖率、温度停止阈值及压力时长，按 OEM/合同要求设置。
3. **身份核验**：有 NVIDIA GPU 时先运行“身份交叉检查”。按 UUID 对齐 nvidia-smi、Linux PCI 与 CUDA，检查架构、容量和已知答案。实物标签及厂商来源仍待人工核验；矛盾项保留失败，不允许加载测试掩盖它。
4. **整机检查**：选择“整机检查（无需 GPU）”，运行 CPU/RAM/结果盘有限抽查及前后 SMART/BMC 健康采集。此项目在有 GPU 的服务器也可独立执行。
5. **硬件负载**：选择 GPU 硬件项目，执行显存同时分配、地址模式写读、独立 CPU 抽样复核、计算压力。Ampere 及更新架构用 BF16，较老兼容架构用 FP32。单卡不要求跨卡 NCCL；多卡按实际数量运行通信正确性检查。
6. **按需扩展**：资源满足后选择预置模型或较长持续压力。公测/MLPerf 是独立有条件项目；其他型号/卡数不会获得与 8×B300 的有效百分比。
7. **运行监控**：同页实时查看阶段、温度/功耗、日志、异常。停止任务后等待启动器、进程组和本任务容器清理完成；不要直接关机代替正常停止。缺失遥测、过温、退出失败均不能成为 PASS。
8. **报告与证据**：页面显示实测 CPU、DIMM、磁盘、接口、GPU 清单与本次范围；打开 HTML/JSON，下载 `evidence.zip`。未执行/不适用与通过分别保留，核对测试参数和覆盖率。证据包含序列号、UUID、主机信息，分享前复核。
9. **采购复核**：“采购验收尚未完成”始终独立于技术结果。按 [采购验货要求](采购验货要求.md) 补齐合同配置、全部 RAM/磁盘/NIC、OEM 诊断、供电/冷启动及人工复核。

## 范围与结果解释

| 项目 | 本版本实际覆盖 | 未完成的内容 |
|---|---|---|
| CPU/RAM/结果盘 | 已知答案 CPU；默认 256 MiB RAM；128 MiB 临时文件写读校验 | 全核长测、全 RAM、所有物理 SSD 全介质诊断 |
| GPU 显存 | 默认目标 85%，同时分配后写读全部已分配块；容量与累计验读字节分别记录 | 系统占用/保留区、所有地址、长期老化 |
| ECC/行重映射 | 支持且可读时复核前后/历史；异常不能忽略 | 无 ECC 的卡不能标为 ECC 已验证；缺失字段需注明范围 |
| NCCL/NVLink | 多卡通信与已暴露链路证据 | NCCL 成功不证明流量经 NVLink；无 NVLink 不等于假卡 |
| DCGM | 支持的数据中心设备按本机诊断结果复核；B300 必需项保留严格检查 | 消费级设备不承诺 DCGM 支持；不替代 OEM 离线诊断 |
| 型号/采购承诺 | 内置架构规则 + 多视角证据 + 指定型号/数量核对 | 来源/保修、准确容量 SKU、CPU/SSD/PSU 配置仍须书面 BOM 和厂商确认 |

缺工具、权限不足、未知型号、字段缺失及测试覆盖不足不会自动变为合格；SKIP/NOT_TESTED/NOT_APPLICABLE 都不能被当成已测试通过。

## 命令行备用

```bash
# 纯整机检查，无 GPU / Docker 依赖
bash run.sh server /data/server-acceptance/cpu-001
# 任意实际卡数的 NVIDIA 身份检查
bash run.sh identity /data/server-acceptance/id-001
# 明确采购目标（例：4 张 H100），压力 1 小时
python3 run_authenticity.py --profile authenticity --hardware-profile h100 --gpus 4 \
  --seconds 3600 --memory-fraction 0.85 --max-temp 85 --out /data/server-acceptance/h100-001
```

型号规则来源：[NVIDIA CUDA GPU 架构表](https://developer.nvidia.com/cuda/gpus)。镜像/设备可见性参见 [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/docker-specialized.html)；兼容运行时参见 [CUDA release notes](https://docs.nvidia.com/cuda/cuda-toolkit-release-notes/index.html)。官方支持会更新，部署前以实际 GPU/软件版本重新核对。
