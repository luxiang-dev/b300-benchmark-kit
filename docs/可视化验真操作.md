# 8×B300 整机核验与可视化操作

适用 Ubuntu 22.04/24.04、单节点 8 张物理 B300。操作界面和报告为中文，无 CDN、在线图表或云端依赖。可在服务器本地浏览器操作，也可从 Windows 浏览器通过 SSH 操作同一个服务。

**这是可复核的身份、容量、功能和稳定性检查，不是厂家真伪认证。** 软件观察依赖主机、驱动和固件；恶意修改这些层时，工具无法证明来源。最终应把 8 张卡的板标签、序列号、采购记录和 BMC 清单交给服务器厂商核对。项目的 CPU/模拟测试不能替代你的 B300 实测。

## 1. 测试内容与范围

| 项目 | 执行内容 | 如何解释 |
| --- | --- | --- |
| 主机身份 | NVIDIA XML、UUID、序列号、VBIOS、PCI/sysfs、驱动、拓扑 | 交叉发现型号、设备号、重复身份或资料缺失 |
| CUDA 身份 | 每张卡的 CUDA UUID/PCI 地址、架构、容量、FP32/BF16 已知答案 | B300 应为计算能力 10.3；小计算正常不等于整卡验收 |
| HBM 容量 | 默认同时分配约 85% 总显存，三轮地址相关模式写入后读回 | 每卡显示实际分配量和覆盖率；累计读验字节不是容量；保留空间不测试 |
| 整机平台 | CPU/RAM/磁盘/NIC/NUMA/BMC 清单，CPU 计算、256 MiB RAM、128 MiB 临时磁盘文件抽查 | 功能抽查，不覆盖全部 RAM/磁盘；缺少工具或权限会明确提示复核 |
| GPU 压力 | 默认 600 秒 BF16 GEMM、显存负载 | 遥测异常或达到温度阈值停止；短时通过不能保证长期稳定 |
| 八卡通信 | PyTorch NCCL 正确性、官方 nccl-tests 固定口径 all-reduce | 比较整机互联表现，性能差距本身不能证明假卡 |
| 硬件诊断 | 主机 DCGM 4.4+、级别 3 诊断 | 缺失或跳过不能计为全部完成 |
| 模型功能（可选） | Qwen/SDXL；独立 DeepSeek-R1 MLPerf v6.0 Offline 扩展 | 必须另外准备权重/数据；DeepSeek 是整机输出 Tokens/s |
| 原始证据 | 前后 XML、每卡 JSON、日志、遥测、HTML/JSON、SHA256 manifest 和 ZIP | 哈希用于复核本地文件变化，不是厂商签名 |

NIC 线速与错误恢复、全部主机 RAM 的压力、完整磁盘介质诊断、BMC 电源/风扇故障注入和厂商现场诊断不在自动功能抽查覆盖范围内。请按机型验收规范另行执行，不能从本项目 PASS 推断这些项目已通过。

## 2. Ubuntu 主机前提

使用能访问 Docker 和 GPU 的运维账号；主机有 Bash、Python 3.10+、`nvidia-smi`。完整 GPU 测试需要：

- 8 张 B300，MIG 关闭，ECC 开启并可读取，没有其他 GPU 计算任务。
- 机型兼容的 R580+ 数据中心驱动、NVIDIA Container Toolkit，以及厂商要求的 Fabric Manager/NVLSM 配置。
- 本地 GPU 镜像。DCGM 4.4+ 和 hostengine 用于完整诊断；未准备时报告 INCOMPLETE。
- 结果目录位于本地 SSD/NVMe，有足够空间并可写。不要混入以前的测试结果。

界面不会自动安装驱动、修改功耗/MIG/ECC、提权或重启服务器。基础安装方法参见 [总使用说明](使用总览.md) 和 [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html)。

先确认：

```bash
nvidia-smi
python3 --version
docker info
dcgmi --version
```

读取内核日志、SMBIOS 和 BMC 可能需要额外权限。缺少权限时保留错误和 REVIEW/SKIP，不能用空白数据证明没有故障。

## 3. 准备离线资源

在与服务器 CPU 架构一致的联网 Linux/Docker 准备机上：

```bash
git clone https://github.com/luxiang-dev/b300-benchmark-kit.git
cd b300-benchmark-kit
# 核验硬件，不下载 Qwen/SDXL 权重
bash prepare_offline.sh --hardware-only
python3 bundle.py verify --hardware-only
```

脚本构建 GPU 运行镜像与固定 nccl-tests，导出 `images/b300-test.tar`、记录镜像 ID/架构并生成 `hardware.sha256.json`。镜像仍较大，应按实际构建大小留空间；这条路线省掉约 23 GiB 的模型权重下载。

若还要执行 quick/full/burn 模型测试，改为完整基础包：

```bash
bash prepare_offline.sh
python3 bundle.py verify
```

不要在上述两条准备路线运行期间更新源码。代码/文档修改会使旧 seal 失效；在可信准备机重新 `seal` 相应包后复制。已有完整基础包同样可以执行 identity/authenticity。DeepSeek 资源独立准备，见 [专项说明](../README_DeepSeek_MLPerf.md)。

将完整准备目录复制到目标 Ubuntu 本地盘，例如 `/data/b300-benchmark-kit`，保留目录结构、Linux 权限和 UTF-8/LF。不要只复制 Python 源码而遗漏镜像、清单与文档。

经 Windows 搬运硬件包时，已有准备目录可用 `copy_to_disk.ps1 -DiskRoot E:\ -HardwareOnly`；它校验硬件 seal 并排除模型、Git 和测试结果。请使用实际移动盘根目录，脚本不会格式化磁盘。

```bash
cd /data/b300-benchmark-kit
python3 bundle.py verify --hardware-only   # 完整包则去掉此参数
```

## 4. 启动控制服务

在目标 Ubuntu 的项目目录启动，结果会保存到指定目录：

```bash
python3 dashboard.py --port 8765 --results /data/b300-results/dashboard
```

服务只绑定 `127.0.0.1`。保持终端运行；用终端复用工具可保留会话。默认镜像为 `b300-test:1.0`，需要时用 `--image` 指定本地镜像。`--max-temp 85` 是默认停止阈值，按厂商规定调整后重启服务。不要将端口直接暴露到公网。

**方式 A：Ubuntu 本地浏览器**

打开 `http://127.0.0.1:8765`。

**方式 B：Windows 浏览器**

保持 Ubuntu 上的服务运行。在 Windows PowerShell 执行，把 `USER` 和 `SERVER` 换成实际 SSH 用户与主机：

```powershell
ssh -N -L 8765:127.0.0.1:8765 USER@SERVER
```

保持 SSH 窗口运行，再在 Windows 浏览器打开 `http://127.0.0.1:8765`。浏览器地址和服务器端口应保持一致；本地端口已占用时，将服务端 `--port` 和转发两端端口一起改为例如 8766。SSH 使用你已有的账号/密钥，网页无需存放服务器密码。

## 5. 界面逐步操作

1. **检查准备状态。** 查看是否有 8 张真实设备、ECC/MIG 状态、镜像、模型和 DeepSeek 资源。缺失项目会说明原因；界面不生成示例卡或示例性能。
2. **导入离线镜像。** 在准备包完整且 Docker 可用时点击“导入离线镜像”。先验证封装哈希，再执行本地 `docker load`，不拉取远程镜像。也可手动执行 `docker load -i images/b300-test.tar`。
3. **身份交叉核验。** 先查看每卡 PCI、UUID、序列号和 CUDA 证据。有错误型号、缺卡、MIG 或缺镜像时仍可采集主机证据；无法运行 CUDA 的部分会明确缺失，不能计为完整通过。
4. **整机硬件验真与稳定性。** 服务器空闲后运行真实性流程。自动进行身份、平台功能抽查、每卡 HBM 地址模式、默认 10 分钟 GPU 压力、八卡通信、公测对比和 DCGM。10 分钟仅指压力阶段，整体还包括初始化、内存读验和诊断时间。
5. **观察实时结果。** 查看 GPU 温度/功耗曲线、当前阶段和原始日志。空白是没有观测数据；运行中的阶段不显示完成。一次仅允许运行一个作业。同一用户启动第二个控制器也会被 GPU 作业锁阻止。
6. **必要时停止。** 点击停止先终止本任务进程组，并清理属于本作业的容器；保留已采集证据，结果为 CANCELLED。温度达到阈值、遥测丢卡/重复身份/异常数据时自动停止并记为失败。导出阶段等待封存完成。
7. **可选模型与公测。** 完整基础包可继续 quick、compare、full、burn；长稳可选择压力秒数。只有准备好独立官方环境后才运行 DeepSeek。界面启动的重负载均有主机温度监控。
8. **下载和复核。** 打开中文 HTML 报告，再下载 `evidence.zip`。逐张核对身份、实际容量/覆盖、错误、跳过和公测条件。对照 8 张实体板标签与 BMC 清单，请厂商确认。

控制服务重启后会显示已有作业；被中断的作业显示 INTERRUPTED。它不会自动恢复重负载。重新运行前先确认旧进程和容器已退出、GPU 空闲。

## 6. 报告结论

| 结果 | 含义与下一步 |
| --- | --- |
| 身份 CONSISTENT | 本次可观察证据与已知 B300 特征一致；继续硬件/厂商复核 |
| 身份 REVIEW | 缺少 CUDA、序列号、已知 SKU 或其他可观察证据；补齐再查 |
| 身份 FAIL | 出现型号/架构/身份/计算等矛盾；查看具体 finding |
| 总体 PASS | 本次选定并运行的项目通过，不是“保证正品” |
| 总体 REVIEW | 有权限、缺失证据、覆盖等事项需要人工复核 |
| 总体 INCOMPLETE | 必需阶段缺失或跳过，例如 DCGM 未安装 |
| 总体 FAIL | 错误、过热、核验矛盾或非正常退出；保留日志排查 |
| CANCELLED / INTERRUPTED | 用户停止或控制服务中断，不能按全部通过解释 |

公测比较是性能参考。驱动、软件、功耗、CPU/NUMA、互联、模型精度和数据口径都可能造成差距。不要把固定百分比当作假卡或硬件合格线。

`identity` 只要求身份阶段；它不代表其他硬件项目已执行。身份子结论与总报告可不同，例如身份一致但内核 Xid 导致总体 FAIL。

## 7. 命令行备用入口

网页和 CLI 共用结果格式。输出目录必须全新：

```bash
# 先采身份（环境不完整也会保留主机证据）
bash run.sh identity /data/b300-results/identity-001
# 默认8卡、约85% HBM、600秒压力
bash run.sh authenticity /data/b300-results/auth-001
# 自定义压力时长、显存比例及厂商温度阈值
python3 run_authenticity.py --profile authenticity \
  --out /data/b300-results/auth-002 --gpus 8 --seconds 1800 \
  --memory-fraction 0.85 --max-temp 85 --image b300-test:1.0
```

运行真实 GPU 流程需要 Linux；Windows 仅可打开界面预览：

```powershell
python dashboard.py --preview --port 8765
```

预览不控制远程 GPU、不产生真实性结论。服务器控制服务必须在 Ubuntu 上启动。

CLI 退出码：0 表示通过，1 表示失败，2 表示需复核/未完成，用户取消一般为 130。请同时阅读报告中的原因；任何采集缺失都不是成功证据。

## 8. 证据保存与常见问题

每次作业保存到唯一子目录。重点文件：`identity-host.json`、`identity-gpu*.json`、`identity-summary.json`、`server-summary.json`、`memory-gpu*.json`、`before.xml/after.xml`、`telemetry.csv`、`stages.tsv`、`summary.json`、`report.html`、`run-result.json`、`evidence-manifest.json`、`evidence.zip`。`run-result.json` 是网页作业的最终记录；实时变化的 `job.json` 不进入封存哈希。CLI 不创建网页作业记录。

- **网页打不开：** 检查 Ubuntu 服务终端、SSH 转发窗口、端口一致性，地址应为 localhost/127.0.0.1。
- **按钮不可用：** 按准备状态补齐工具、空闲窗口、镜像或资源；只读预览禁止启动。身份采集可以在不符合完整负载前提时运行。
- **显存覆盖低于目标：** 报告实际已测容量；可能存在驱动占用或可用显存不足。累计三轮验证不能算三倍物理容量。清理其他计算任务后重测，结合 DCGM 和厂商离线诊断检查保留区域。
- **封装校验失败：** 重新复制或在可信准备机重新制作；不要删掉校验去运行。
- **内核/BMC 信息读不到：** 获取相应运维权限或补充人工日志，不要将其解释为零错误。
- **DCGM 跳过：** 按厂商流程准备 B300 兼容 DCGM 4.4+/hostengine；使用新目录重测。
- **NCCL 偏慢：** 先核对 NVLink/NVSwitch 链路、NUMA、Fabric Manager、功耗和软件口径，再比较公测。

结果包含序列号和主机信息。保留原始 ZIP，分享前检查内容；源码仓库默认忽略运行结果、权重、镜像和本机 seal。

## 9. 规格来源与人工确认

- [NVIDIA CUDA GPU 列表](https://developer.nvidia.com/cuda/gpus)：B300 计算能力 10.3，B200 为 10.0。
- [R580.95.05 支持设备](https://download.nvidia.com/XFree86/Linux-x86_64/580.95.05/README/supportedchips.html)：已知 B300 SXM6 AC 变体。未知变体需 OEM 复核，不能仅凭不同子设备号断言假卡。
- [Blackwell Ultra 数据表](https://resources.nvidia.com/en-us-gpu-resources/blackwell-ultra-datasheet?xs=443990) 与 [DGX B300 用户指南](https://docs.nvidia.com/dgx/dgxb300-user-guide/introduction-to-dgxb300.html)：不同资料包含 270 GB/288 GB 容量表述；按具体 SKU 核实，区分 GB、GiB 和系统保留，不能强制要求 288 GiB。
- [nvidia-smi 文档](https://docs.nvidia.com/deploy/nvidia-smi/index.html)：序列号应与板标签核对，UUID 是软件识别项。
- [DCGM 诊断范围](https://docs.nvidia.com/datacenter/dcgm/latest/learn/modules/dcgm-diagnostics.html)：在线诊断不能替代现场离线诊断。
- [NVIDIA Attestation 兼容性](https://docs.nvidia.com/attestation/attestation-client-tools-sdk/latest/sdk_compatibility.html)：适用特定 CC/PPCIE 与虚拟机环境，本项目没有将它冒充为所有 B300 通用认证。

建议验收顺序：保存身份 → 执行硬件流程 → 长时间稳定性/模型（按需）→ 同配置重复性能测量 → 厂商确认实物及采购来源。
