# 通用离线资源准备与断网验练

本页覆盖 NVIDIA 各型号及无 GPU 服务器的通用验货基础包，以及独立的 8×B300 DeepSeek-R1 / MLPerf Inference v6.0 Offline 扩展。**本次只提供清单、核对工具和操作流程，不下载资源。** GitHub 源码 ZIP 不包含镜像、模型、数据集或驱动。文件齐全、哈希正确、目标机实际能运行是三个不同的检查。

## 1. 选择资源范围

| 范围 / 核对参数 | 用途 | 要准备的资源 |
|---|---|---|
| `server` | 无 GPU，或单独检查主机部件 | 源码及本地网页、Python 3.10+、主机工具与权限；无需 Docker/模型 |
| `hardware` | 任意支持型号、1–64 张 NVIDIA GPU 的身份与硬件负载 | server + 匹配的驱动/容器环境 + 无模型 GPU 镜像和硬件包封装 |
| `full` | Qwen/SDXL 基础功能 | hardware + 三组固定版本模型 + 完整包封装 |
| `all` | 基础包与 DeepSeek 资源一并核对 | full + 下述独立 DeepSeek 全套资源；DeepSeek 实际测试仍只适用 8×B300 |

这些名称表示离线资源范围，不表示已完成采购验收。其他 NVIDIA 型号可使用通用流程，不应为了验货下载不能适用的 B300 专项。小显存、较旧架构优先选择硬件包；预置 BF16 模型另有显存与架构要求。

## 2. Ubuntu 主机资源：安装好或带齐安装材料

准备机应与目标机的 Ubuntu 版本、CPU 架构（amd64/arm64）及所用容器架构相匹配。主机驱动还要匹配实际 GPU、目标内核与 OEM 要求。**不提供一个固定驱动安装包来覆盖全部硬件。** 正常运行容器测试无需在宿主机额外安装 CUDA Toolkit、PyTorch 或模型 Python 依赖。

| 资源 | 准备/核对事项 |
|---|---|
| Python 3.10+、Bash、coreutils | 运行控制页面、主机采集、哈希与启动器；控制页面使用 Python 标准库 |
| util-linux、procps、pciutils、iproute2、numactl、lm-sensors | lscpu/lsblk/free/lspci/ip/rdma/NUMA/传感器；有命令不等于存在传感器或 RDMA 设备 |
| dmidecode、smartmontools、ipmitool、systemd 日志 | SMBIOS、SMART、本地 BMC、内核 RAS；同时准备读取权限及 OEM 支持。虚拟机、无 BMC、受限内核日志仍可能缺证 |
| NVIDIA 驱动（GPU 流程） | 安装并验证 nvidia-smi；若目标机还需离线安装，保留对应本地仓库/安装材料、完整依赖、签名信息及版本记录 |
| 内核 headers / DKMS / 编译及 Secure Boot 材料 | 仅在驱动安装需要时准备，headers 必须匹配目标运行内核；离线更新内核应同步准备新内核配套材料，预先完成 MOK/签名操作 |
| Docker Engine、CLI、containerd | 基础与 DeepSeek 容器需要；保留所选版本的 deb 与依赖。buildx/compose 按准备过程实际使用纳入 |
| NVIDIA Container Toolkit | toolkit、toolkit-base、libnvidia-container-tools、libnvidia-container1 版本一致，联网阶段配置 Docker 并实际验证 GPU 容器 |
| DCGM / hostengine | 适用的数据中心卡诊断；B300 严格流程要求兼容版本。消费级卡不假定支持 DCGM；不支持与未准备均不记为已测 |
| Fabric Manager / NVLSM / OEM 固件配置 | 仅适用的 NVSwitch 系统按驱动/OEM 配套准备；普通 PCIe/消费卡不要求虚构这些资源 |
| 浏览器 | 目标 Ubuntu 本地浏览器或局域网另一台机器的浏览器；页面 JS/CSS 在项目内，无 CDN、外部字体或在线前端依赖 |
| 采购资料 | BOM、序列号、OEM 诊断/保修资料、合同指标；软件离线运行不替代这些验货证据 |

若服务器已安装所需工具，可以先核对并试跑，无需重复安装。若要全新离线安装，建议在与目标系统一致的干净 VM/容器/系统环境中收集 deb **完整依赖闭包**，并在离线副本上试装；在已有软件的不同机器执行一次 `apt --download-only` 可能漏依赖。系统重装本身另需 Ubuntu 安装介质。

参考：[NVIDIA Ubuntu 驱动本地仓库](https://docs.nvidia.com/datacenter/tesla/driver-installation-guide/ubuntu.html)、[Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)、[DCGM](https://docs.nvidia.com/datacenter/dcgm/latest/user-guide/getting-started.html)、[Docker Ubuntu deb 安装](https://docs.docker.com/engine/install/ubuntu/)。版本以选定且验证过的准备环境为准，离线现场不追随 latest 更新。

## 3. 基础 GPU 包

完整复制项目源码、`dashboard/`、`docs/`、锁文件和 vendored NCCL 源码。`bundle.py` 中的 `CODE` 是实际封装清单，禁止只拷贝几个启动脚本。

| 资源 | 固定依据 / 注意事项 |
|---|---|
| `images/b300-test.tar` | 最终构建镜像的 Docker save 归档，包含 PyTorch/CUDA/NCCL、Python 依赖、编译后的 nccl-tests；文件名兼容历史，不限制 GPU 型号 |
| `images/runtime.inspect.json` | 最终镜像 ID/架构信息，与归档和封装一起保存 |
| `hardware.sha256.json` 或 `bundle.sha256.json` | 分别对应硬件包或完整模型包；复制前后验证。修改源码/镜像后必须重新封装 |
| `requirements.txt` 及镜像内 `/opt/b300-environment.txt` | 最终 Python 依赖安装在镜像里并保存实际环境版本；离线运行不执行 pip install |
| `vendor/nccl-tests-v2.17.6.tar.gz` | revision `da0b547b1b9c6e3b1d4c15578087874522ae3761`；SHA256 `d589c597110da30b52d462269ae0d0381c46811a7b266db09fe865d9aaff31c1` |
| 镜像内 NCCL binary + build-manifest | 在准备阶段针对镜像 CUDA 编译；预检核对 binary 与源码绑定。实测通信仍需运行多卡测试 |

默认镜像使用 CUDA 13。较旧 GPU 应在联网准备时通过 `BASE_IMAGE` 选择兼容镜像，使用 `TARGET_ARCH=amd64` 或 `arm64` 匹配目标；应先确认驱动、CUDA、PyTorch 支持该 GPU 的计算能力，再构建并验证。不能保证默认镜像覆盖全部历史 NVIDIA 型号。

联网准备机上的现有入口（本次不执行）：

```bash
# 只验硬件，不下载大模型
TARGET_ARCH=amd64 bash prepare_offline.sh --hardware-only
python3 bundle.py verify --hardware-only

# 需要预置模型功能：与上一方案二选一
TARGET_ARCH=amd64 bash prepare_offline.sh
python3 bundle.py verify
```

| 准确率 venv | `.dsr1-acc-venv/` 全部内容和 `.requirements_hash`；Python/包依赖、editable 路径须能在最终镜像及原工作路径中解析 |

## 5. 通用目录封装、运输与空间规划

新增 `offline_manifest.py` 可对任意准备完成的资源目录记录 SHA256、大小、目录、软链接文字和 Linux 权限。可分别封装主机 deb 目录、DeepSeek checkout、scratch、镜像目录；也可将这些放进一个共同根目录封装。它不下载、不跟随软链接，也不证明文件来源或运行兼容性。含外部目标的软链接需把真实目标目录另行封装、复制并验证。

```bash
# 停止下载、缓存生成和其他写入后，在准备机封装
python3 offline_manifest.py seal --root /data/prepared-deepseek \
  --manifest /data/prepared-deepseek.sha256.json
# 将目录和可信清单一起运输，目标机核对，增加/缺失/篡改均失败
python3 offline_manifest.py verify --root /data/prepared-deepseek \
  --manifest /data/prepared-deepseek.sha256.json
```

清单应从可信准备机留存；攻击者同时修改文件和清单时，哈希不能鉴定真伪。基础模型和 DeepSeek 模型仍额外核对项目锁文件的来源哈希。

DeepSeek 优先使用 ext4/XFS。若中转盘为 exFAT/NTFS，应先在 Linux 用 tar 保存 `.git`、可执行权限、软链接及完整目录，到目标 Linux 文件系统解包；不要将 venv 从 Windows 重新安装后视为同一环境。FAT32 无法容纳大于 4 GiB 的文件。含绝对路径链接时保持 scratch 挂载路径，并再次运行专项 check。复制过程中禁止修改源目录。

实际空间 = 模型 + 两种最终镜像 + 源码/编译产物 + 数据/缓存/venv + 打包或解包的临时副本 + 结果及余量。仅模型就约 **417.72 GiB**；建议 DeepSeek 准备机至少预留 1 TB，具体取决于是否同时保留归档和展开副本，1 TB 不是充分条件。先测量实际文件与可用空间再运输。

## 6. 可视化核对与断网运行

1. 在准备机按所选范围完成资源制作，在目标服务器安装或导入本地依赖；此步骤不由页面自动安装系统软件。
2. Ubuntu 启动 `python3 dashboard.py --host 0.0.0.0 --port 8765`。本地浏览器访问 `http://127.0.0.1:8765`，局域网浏览器访问服务器 IP；Windows 也可经 SSH 隧道访问。
3. 页面选择 **离线资源核对**，选择四档范围之一，点击核对。页面展示镜像/封装、模型文件与来源哈希、主机工具、DeepSeek 缺项以及实时日志；报告和 summary.json 可以下载。核对任务不需要 GPU/Docker，可以在资源不完整时运行。
4. `HASH_VERIFIED` 是本次已验证来源哈希或封装；`PRESENT_UNVERIFIED` 仅表示存在；`MISSING/INVALID` 表示缺失/不符。页面明确保留“断网运行未执行”，不会自动宣布离线就绪。大权重逐文件哈希会耗时，应保留完整输出。
5. 在目标机关闭外网/出口后执行下列预检。GPU 预检需要空闲窗口和任务锁；只使用本地镜像，不拉取，不安装，容器无外部网络。基础预检运行逐卡小矩阵 CUDA 正确性、NCCL binary 绑定、可选 tokenizer/config 加载；DeepSeek 运行现有完整专项 check。CPU `server` 范围直接执行整机检查。
6. 回到页面，先整机检查/身份交叉检查，再真实性负载、快速/完整模型测试；适用时再跑 DeepSeek 性能及准确率。实时看阶段、温度、日志和中止状态，下载证据。**预检的小矩阵或 config 加载不替代真实推理与全负载。**

```bash
python3 offline_resources.py --scope all --verify-hashes --out /data/results/offline-inventory
# 退出码 1=失败，2=待补齐/待实机验证；核对工具不会返回离线已就绪的 0

bash verify_offline.sh server /data/results/offline-server
bash verify_offline.sh hardware    # 硬件包
bash verify_offline.sh full        # 完整基础模型包

# 全部或 DeepSeek 专项另需这些本地路径
export MLPERF_REPO=/data/inference_results_v6.0
export MLPERF_SCRATCH_PATH=/data/mlperf-deepseek-storage
export MLPERF_IMAGE=b300-deepseek-mlperf:6.0
export MLPERF_IMAGE_ARCHIVE=/data/images/b300-deepseek-mlperf.tar
export MLPERF_IMAGE_INSPECT=/data/images/b300-deepseek-mlperf.inspect.json
bash verify_offline.sh all         # 基础 + DeepSeek 预检
# bash verify_offline.sh deepseek  # 只预检专项
```

设置 DeepSeek 环境变量后再启动 dashboard，控制服务才能继承它们。外部镜像的归档/inspect 仅列存在状态，完整性请用通用 manifest 验证。不要把截图中的绿色状态或旧 PACKAGE_STATUS.json 当成本次实测结果。

公网映射需要实际网络；彻底无网时使用本机/局域网可视化。HTTPS 证书续签、DNS、公网代理以及外部 BMC 服务不属于离线包可以替代的功能。模型测试不依赖远程服务；DeepSeek 容器内 localhost 服务是本地进程通信。
