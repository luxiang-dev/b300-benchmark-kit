        03 — OPERATOR GUIDE

        全流程操作说明

        离线准备 → 本地运行 → 证据导出
        1
        准备 Ubuntu 测试主机推荐 Ubuntu 22.04 / 24.04
        ⌄

        GPU 项目安装适配实际型号的 NVIDIA 数据中心驱动、Docker 与 NVIDIA Container Toolkit。确认卡空闲、MIG 关闭；支持 ECC 时开启。只有装有 NVSwitch 的机器才核对 Fabric 服务。无 GPU 的整机检查只需 Python 3，无需 Docker 或 NVIDIA 驱动。使用能读取内核日志的运维账号。

        python3 --version nvidia-smi docker info

        通用硬件流程支持 1–64 张 NVIDIA GPU，也支持无需 GPU 的整机检查。NCCL 公测及 DeepSeek TP8/EP8 项目要求卡数与参考条件一致；单卡结果不能直接套用整机参考。

        2
        提前准备离线资源下载、构建与校验在有网 Linux 上完成
        ⌄

        身份与硬件验真不需要大模型权重。先在 CPU 架构相同的有网 Linux 主机准备硬件测试镜像，再复制整个准备包到目标服务器本地 SSD。

        bash prepare_offline.sh --hardware-only python3 bundle.py verify --hardware-only

        在工作台选择“离线资源核对”，按无 GPU、硬件、基础模型或基础加 DeepSeek 四档核对缺项与哈希。然后点击“导入离线镜像”，程序先校验归档再导入。Qwen / SDXL 功能测试需要完整基础包，准备时去掉 --hardware-only。

        DeepSeek 单独准备固定官方源码、FP4 权重、数据、准确率环境与镜像，并设置 MLPERF_REPO、MLPERF_SCRATCH_PATH、MLPERF_IMAGE。完整资源清单见项目里的 docs/离线资源总清单.md，专项细节见 README_DeepSeek_MLPerf.md。

        本页面不会自动下载或安装。文件核对不能代替实际运行；目标机执行 bash verify_offline.sh full（全部资源用 all）断网预检，再通过页面运行硬件和模型测试。

        3
        启动可视化工作台支持本地、局域网与公网映射
        ⌄

        在 Ubuntu 项目目录启动服务。保留终端运行，然后在 Ubuntu 浏览器打开 http://127.0.0.1:8765。

        python3 dashboard.py --host 0.0.0.0 --port 8765 --image b300-test:1.0

        可直接通过服务器 IP 或你映射的公网 URL 操作；映射端配置 HTTPS/认证，代理改写 Host 时加 --public-origin。也可从 Windows 在 PowerShell 新开 SSH 隧道，把下方用户名与服务器地址替换成实际值，再在 Windows 浏览器打开相同地址。

        ssh -N -L 8765:127.0.0.1:8765 用户名@Ubuntu服务器IP

        不要关闭服务终端或 SSH 隧道。结束负载时先点击“停止任务”，等待清理完成。

        4
        逐层检查身份与稳定性先检查身份，再执行真实负载
        ⌄
        1. 先运行“身份交叉检查”，复核硬件与驱动提供的多个身份信号。
        2. 运行“真实性负载”，采集服务器清单，抽查 CPU、256 MiB RAM 与 128 MiB 结果盘文件，再验证 GPU 显存、计算与互联；观察每张卡的遥测及错误。
        3. 8 卡整机继续执行“NCCL 公测对比”，检查互联性能与参考数据的测试条件。
        4. 运行“快速功能”或“完整功能测试”；需要长压力时再运行“持续压力”。
        5. 准备独立资源后可执行 DeepSeek-R1 MLPerf v6.0 Offline，读取性能与准确率两份证据。

        运行期间保持主机空闲，观察温度、功耗与原始日志。全 RAM、全盘、NIC 远端线速和 OEM 人工验收需另行完成。出现异常时停止，保存日志并排查供电、散热、驱动和硬件。

        5
        复核结论并保留证据报告、原始日志与校验清单一起保存
        ⌄

        在“运行与证据”选择本次任务。检查全部阶段、遥测覆盖、ECC/Xid 与报告说明；下载报告、原始文件及证据归档。身份一致性与负载通过可提供较强的软件证据。继续向厂商或供应商核验序列号、部件编号与采购记录，并保留卡/服务器铭牌照片、BMC 清单和厂家回复。将实物信息与本次采集证据逐项对照。

        PASS本次要求的检查通过FAIL有失败或明确异常REVIEW需要人工复核证据INCOMPLETE未完成全部要求
        ◎

        技术通过 ≠ 采购验收完成

        软件检查可以交叉验证身份、架构特征、显存与实际性能，不能代替采购 BOM 比对、厂商认证或实物检查。工作台不会自动给出“采购验收通过”。

        公测对比看条件

        8×B300 的整机结果应使用相同卡数、场景、模型与精度。单卡结果不能直接与 8 卡 MLPerf 或 NCCL 公测比较。
